# Design change control

## Authority

The canonical index and the designated specialist documents are normative. Prompts, drafts, historical notes, and generated summaries are informative unless explicitly promoted.

## Change procedure

1. State the decision or contradiction.
2. Identify affected pillars, systems, content, interface, data, tests, and acceptance criteria.
3. Record the decision in the decision log.
4. Update the canonical source and traceability.
5. Mark downstream implementation work.
6. Retire or label superseded text.

## Conflict rule

The canonical source for the affected domain wins. If authority is unclear, implementation is blocked for that decision until the owner records a ruling.

## Freeze

The first prototype tranche is frozen to the current canonical set. Runtime hypotheses may change after evidence; identity and scope changes require explicit change control.
