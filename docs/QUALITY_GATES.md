# Quality gates

## Gate Q0 — Concept clarity

Pass when the one-sentence promise, pillars, anti-pillars, audience, rating intent, and differentiator are agreed and visible in playtests.

## Gate Q1 — Vehicle feel

Pass when blind playtesters can control the vehicle quickly, describe its weight, understand impacts, and voluntarily replay a five-minute test.

## Gate Q2 — First playable

Pass when the full loop works without designer intervention and players understand objective, damage, workshop, reward, and one consequence.

## Gate Q3 — Vertical slice

Pass when the slice reaches target presentation quality, has no known blocker defects, supports required accessibility options, and produces positive evidence from structured playtests.

## Gate Q4 — Alpha

Pass when all core systems exist, performance budgets are met on target hardware, save/load and replay tests pass, and content pipelines are stable.

## Gate Q5 — Beta

Pass when content is complete, critical accessibility issues are closed, regression tests are reliable, crash rate is acceptable, and external playtests identify no systemic confusion.

## Gate Q6 — Release candidate

Pass when platform, legal, localization, rating, performance, accessibility, stability, support, and rollback requirements are signed off.

A gate may be failed even when the code compiles. Evidence is mandatory.
